# 营业时间 JSON 约定

数据库字段为 `hours_json`，前端门店对象映射为 `hours`。保持现有每周时段结构：`default` 是时段数组，每项依次为开始营业的星期、开始时间、结束时间。

```json
{
  "default": [
    ["Mon", "09:00", "12:00"],
    ["Mon", "14:00", "18:00"],
    ["Tue", "22:00", "02:00"],
    ["Wed", "00:00", "24:00"]
  ]
}
```

上例仅说明格式，不是真实门店数据：周一有两个时段，12:00–14:00 为间歇；周二晚间的时段延续至周三 02:00；周三全天营业。

- 星期使用 `Mon`、`Tue`、`Wed`、`Thu`、`Fri`、`Sat`、`Sun`，同一天可以重复出现。
- 时间使用两位小时和分钟 `HH:mm`，按 `Asia/Shanghai` 时区判断，与用户设备所在时区无关。
- 开始时刻包含在营业区间内，结束时刻不包含。例如 09:00–12:00 在 12:00 已结束。
- 结束时间早于开始时间表示跨至次日。该条记录属于开始营业的星期；周日跨午夜可延续至周一。
- 全天营业使用 `00:00`–`24:00`。仅结束时间允许 `24:00`；相同开始和结束时间不会被推断为全天营业。
- `null`、缺少 `default` 或 `{"default":[]}` 表示没有可用于判断的时段，不应解读为门店永久停业。已完整核验的周表中，不营业的星期不填写时段；当前结构没有独立的“已核验休息日”状态。
- 当前判断不处理节假日、临时停业或按日期覆盖，需要实际需求与数据后再扩展。

列表与详情共用 `getOpeningState`，返回 `open`、`closed` 或 `unknown`；空表、格式错误或任何一条时段无效时显示“营业时间待确认”，不会误标为已打烊。Open Now 筛选只包含已确认处于营业时段的门店。

逻辑在 `src/utils/opening-hours.ts`，首页与详情每分钟以及返回前台时重新计算。测试需 Node.js 24，可执行：

```bash
node --test tests/opening-hours.test.mjs
```
