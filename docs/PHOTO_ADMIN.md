# 门店资料后台

后台入口为 `/admin`，包含“封面照片”和“门店特色”。照片功能针对已有门店补封面：搜索店名或地址，筛选待配图门店，选择一张照片，预览后保存或继续下一家。照片关联现有 `venues.image_url`，App 下次加载门店数据时即可读取新封面。

2026 年 10 月 4 日已在现有 Supabase 项目完成初始化及一个管理员账号授权。云端回查为 87 家门店、8 张原有封面、0 张新上传照片；以管理员身份进行的数据库权限检查和门店读取检查通过。账号密码由本人在 Supabase 页面设置，未写入代码或文档。

特色功能的使用、存储约定和筛选范围见 [门店特色说明](tags.md)。特色接口及可维护目录可通过 `supabase/install-feature-admin.sql` 一次安装，已通过本地测试，云端安装尚待确认；此前完成的照片配置仍然有效。

## 日常使用

1. 使用已授权的邮箱和密码登录后台。
2. 在「待配图」列表选店，也可以搜索店名或地址。
3. 点击「选择照片」，或在电脑上拖入一张照片。
4. 确认预览后点击「保存封面」或「保存并下一家」。

照片在浏览器内重新编码为 JPEG，最长边不超过 1600 像素，小图不会放大。原文件上限 20 MB，处理后的文件上限 2 MB；像素重新绘制不会保留原始 EXIF 元数据。支持 JPEG、PNG、WebP、AVIF；HEIC/HEIF 是否可读取取决于浏览器，无法读取时会提示先导出为 JPEG。

封面预览采用居中裁切，与 App 卡片展示方式相同。首版不包含裁切位置调整、多图相册、新增门店或营业时间编辑。

## 一次性云端配置

这是现有 Next.js 项目中的静态管理页，不需要另开后端服务器；权限由 Supabase 验证。浏览器使用公开客户端 key，管理员通过 Supabase Auth 登录，不使用 service_role 或 secret key。

1. 在项目 SQL Editor 执行 `supabase/migrations/202610040001_photo_admin.sql`。该文件中的图片基础地址针对当前恢复的 Supabase 项目，迁移到其他项目时需要替换。
2. 在 Authentication → Users → Add user → Create new user 创建邮箱和密码账号，保留 Auto confirm user。密码由账号本人设置。
3. 按 `supabase/grant-photo-admin.sql.example` 填写该邮箱并执行，只有已确认的账号才能获权。

迁移创建 `venue-photos` 公开照片 bucket、私有管理员名单、权限检查函数及封面保存函数；保留现有门店和图片地址。照片使用新的随机路径，不覆盖旧文件。

为避免已有宽松策略绕过后台限制，迁移会禁止 anon/authenticated 角色直接新增、更新和删除门店；封面修改只经受保护的 RPC 完成。现有公开读取保持不变。`venue-photos` 的新增文件仅允许管理员写入有效门店目录，不允许客户端覆盖或删除照片，其他 bucket 不受这些限制影响。

管理权限位于 `coffee_private.admins`，普通账号不能修改名单。需要撤销权限时由项目所有者删除对应名单行，后续上传和保存请求会被拒绝；无需更换客户端公钥。

## 保存失败及恢复

上传成功、保存失败时，当前页面会保留新照片路径，重试复用已上传文件。RPC 对同一路径的重试幂等，并比较先前图片地址；另一会话已经更换封面时，会提示刷新资料，避免静默覆盖。

上传与数据库更新不是同一事务。上传后放弃编辑、上传响应丢失或页面关闭，可能留下未关联的对象。旧封面也保留用于人工恢复；第一版不自动清理文件。清理前应由所有者核对 `venues.image_url`，避免删除使用中的图片。

## 本地运行和部署

按 README 配置 `.env.local`，使用 Node.js 24：

```bash
npm ci
npm run dev
```

访问 `http://localhost:3000/admin`。本地地址只适用于运行服务的电脑；手机日常使用需要部署到可访问的 HTTPS 地址。生产构建使用 `npm run build`，静态托管应将 `/admin` 映射到 `admin.html`，并上传完整 `out/` 目录。
